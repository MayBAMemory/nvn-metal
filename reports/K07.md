## 做法（`kirby/tools/kirby_xlate.py`）

每个「控制段 + 机器码」组合一个作业，共 27239 个。机器码切分照 `dm/gfx/tools/dmsh_build.py` 的 `job_for()`：
- 图形阶段去掉前 0x30 字节的 NVN 头；
- c1 取机器码的 `[ctrl+0x700, ctrl+0x704)` 这一段。

没有作答表（`shader_facts.tsv` 里没有卡比的键），翻译器遇到需要作答的地方用缺省值，并记成一条说明。作业按每批 400 个交给 dmsh_xlate，再用 spirv-cross 转成 MSL。电脑上没有苹果的 Metal 编译器，这条链只走到 MSL 为止，和 `nometal_run.py` 的路线一样。

```powershell
$env:DOTNET_ROOT = "C:\Users\hy367\scoop\apps\dotnet-sdk\current"
python -I kirby/tools/kirby_xlate.py --shaders D:\kirby-work\shaders --out D:\kirby-work\xlate --jobs 12 --batch 400
python -I kirby/tools/tex_handles.py D:\kirby-work\xlate\spv
```

全量约 10 分钟（Ryzen 5 7500F，12 并发）。每个作业一行的明细在 `D:\kirby-work\xlate\dryrun.tsv`（27239 行，不进 git）。

## 结果

| 阶段 | 数量 | 转成 MSL | 说明 |
|---|---:|---:|---|
| 顶点 | 8741 | 8741 | 其中 3 个要开 `debug`（见下） |
| 片元 | 18416 | 18416 | |
| 计算 | 72 | 72 | |
| 几何 | 10 | 0（实际） | spirv-cross 输出 `unknown main0(...)`，不是合法 MSL，见下 |

- **27229 / 27229 个非几何着色器都能翻成 MSL。** 这还不代表苹果的 Metal 编译器一定能编过，那一步要等 Mac。
- **3 个顶点着色器在优化模式（`debug: false`）下，翻译器内部报 `InvalidCastException`**（`AstOperation` 转 `AstOperand` 出错），分别是 `72c44ef55d7e4fc5.d92432c01c28aa67`、`bb440def156a6261.b23b0219a5c78c78`、`c36d216998c14144.ac698660421d456b`。改成 `debug: true`（跳过 AST 优化器）后全部翻译成功。出包时对这 3 个单独开 `debug`，或者统一按「先优化、失败再用 debug 重试」处理。
- **作答表要回答的问题：0 处。** 贴图类型、图像格式都没有被问到，c1 也没有越界读。原因是 Maxwell 的贴图指令里自带维度，绑定贴图不需要额外作答。卡比可以不要作答表，或者只做一张很小的。顶点属性和片元输出的分量类型目前按 float 处理，要等运行时核对。
- **几何着色器**：10 个键，共出现 50 次，全部来自两个模型：`gfx/Actor/Chara/Kirby/DeformKirby/DumpCar/Model.bfres.cmp` 和 `.../Elevator/Main.bfres.cmp`，即卡比「塞满变形」的两种形态。Metal 没有几何阶段，要另想办法（H3）。影响范围只限这两种形态。

## 贴图句柄布局（对回放层很重要）

61466 处贴图引用**全部是绑定贴图**（`cbuf_slot = -1`，`separate = false`），句柄在常量段 c[2] 中的字节偏移**恰好是 0x20 到 0x118，步长 8，共 32 个**：

```
c[2][0x20 + 8r]  = 组合贴图（贴图 + 采样器）第 r 槽，r = 0..31   ← nn::gfx / nvnCommandBufferBindTexture
c[2][0x120 + 8r] = 图像第 r 槽（卡比只有 2 处引用，与 D2R 相同）
c[2][0x168 + 8r] / [0x568 + 8r] = D2R 用的分离贴图 / 分离采样器（卡比不用）
```

D2R 的出库脚本（`dmsh_build.py` 的 `TEX_BASE = 0x168`）和回放层都按分离句柄表来解析。卡比要加上「组合贴图表从 0x20 起」这一种，归 H3 和 H4。

## 交给 H3 的结论

1. 翻译链本身对卡比基本够用，**不需要作答表**。
2. 3 个着色器要开 `debug` 模式。
3. 贴图绑定要支持「c[2] 0x20 起的组合贴图表」。
4. 几何着色器只影响两种「塞满变形」形态，可以先跳过这些绘制，以后再做模拟。
5. 翻译器支持 alpha 测试（`GpuGraphicsState` 的 `AlphaTestOp` 和参考值，目前在 `dmsh_xlate` 里固定为 `Always`），可以按需出带 alpha 测试的变体，不用手改 MSL。
6. `SetShadersExt` 会改写控制段（见 `docs/gfx.md`）：受影响的着色器，运行时的键和离线的键对不上。
