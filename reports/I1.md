# I1：卡比的 iOS 外壳（kirby/ios）

2026-10-14，Intel Mac 上的 Claude。用法见 [../ios/README.md](../ios/README.md)。

## 做了什么

照 D2R 的 `dm/ios` 做了一个卡比专用的 iPhone App 工程。没有复制 D2R 的外壳：那份有 2600 多行，大半是 D2R 的触屏界面、资源下载和 iCloud 存档，卡比用不上。新写的部分：

| 文件 | 行数 | 说明 |
|---|---|---|
| `kirby/ios/Sources/main.m` | 约 170 | 日志、找 RomFS（根目录要有 `gfx/` 和 `shader/`）、设环境变量、在大栈线程上调 `dm_main` |
| `kirby/ios/Sources/front_ios_kirby.m` | 约 190 | `front.h` 的 iOS 实现、触屏、+/− 小钮、屏幕手柄（`GCVirtualController`）、前后台切换 |
| `kirby/ios/tools/gen_build.py` | | 改自 D2R 那份，取的是 `kirby/host/Makefile`（要处理续行），并且收进 `dm_gamepad.m` |
| `kirby/ios/tools/shlib_ios.py` | | Windows 着色器库 → iOS metallib，可并发，重跑时跳过已编的，失败记进 `failed.tsv` |
| `kirby/ios/run.sh` | | shaders / build / install / romfs / run / log 六个子命令 |
| `kirby/ios/project.yml` | | XcodeGen 工程描述 |

模块内嵌直接用 `dm/ios/tools/gen_embed.py`。`dm/` 下的代码一行没改。

## 先查清的事

1. **卡比宿主按 iOS 目标编，没有一个错误**：49 个文件逐个用 `-target arm64-apple-ios26.0` 编译。
2. **外壳要补的符号只有 5 个**：卡比宿主的全部目标文件按 iOS 链接，缺的是 `front_run`、`front_metal_layer`、`front_game_res`、`front_text_input`、`dm_front_navigation`，外加 CoreGraphics 框架。`front_save_failed` 已有弱定义。这 5 个都由 `front_ios_kirby.m` 提供。
3. **手柄不用另写**：`dm_gamepad.m` 已在宿主的 Makefile 里，卡比的 `hle_hid_kirby.c` 读的就是它写的 `dm_pad_set`。系统的屏幕手柄（`GCVirtualController`）对它来说是一个普通手柄。+/− 走 `dm_input_set`，两路按位或；摇杆给 0 时不会盖掉手柄的摇杆（`hle_hid_kirby.c` 的 `fill`）。

## 验证

```bash
KIRBY_NO_GAME=1 kirby/ios/run.sh build      # 不带游戏内容：编译 + 链接通过，外壳和卡比宿主文件 0 警告
```

用假模块（三个模块各一份 208 KB 的空映像，加上按 `patch_nso.py` 格式写的布局表头）和两个假着色器，把带游戏内容的流程也走了一遍：

- `shlib_ios.py`：合法的 MSL 编成了 `MTLB` 开头的库；故意写错的那个记进了 `failed.tsv`，退出码是 1；重跑时跳过已编的。
- `run.sh build`：可执行文件里 `__dmmainx0/x1`、`__dmsdkx0/x1`、`__dmsubsdk0x0/x1` 六个节都在 `__TEXT`；三个 `__DM<名>W` 段的权限是 rw（`-segprot` 生效了）。`dm/` 里的表、`msl/b-<V>/` 都进了 App。

**没验证的**：签名、装机、在手机上启动。这台 Mac 还没登录 Apple ID，手机在锁屏状态，开发者磁盘映像挂不上（`kAMDMobileImageMounterDeviceLocked`）。

## 碰到的坑

- **`iOS 26.5 is not installed`**：Xcode 26 给任何真机或通用目标（`-destination`）构建，都要先装「iOS 平台」组件，也就是模拟器运行时，约 8 GB。这台机器只剩 25 GB，所以 `run.sh` 改成按 target 加 `-sdk iphoneos` 构建，这样不查这一项。代价是 xcodebuild 不会顺带把手机登记进开发者团队，补救办法写在 README 的「已知限制」里。
- 卡比 Makefile 的链接命令带续行，D2R 的 `gen_build.py` 直接拿去用会出错（`shlex` 报 `No escaped character`）。

## 待决定 / 下一步

1. **账号**：付费还是免费，由用户决定。免费账号签不了「提高内存上限」和「扩展虚拟寻址」两项权限，卡比的内存够不够要实测。
2. **游戏数据**：从 Windows 拷来 `patched/`、`shlib/`、`RomFS/`（见 README 的表），然后依次运行 `run.sh shaders`、`build`、`install`、`romfs`、`run`。这就是 H4 在 iPhone 上的起点。
3. **手机系统比 Xcode 新**：手机 iOS 27.2，Xcode 26.5。按 iOS 26 编的 App 照常能跑；能不能装机、能不能拉日志，第一次连上时确认。
4. 屏幕手柄目前只有左摇杆、A/B/X/Y、L/R。卡比实际要用哪些键（ZL/ZR、右摇杆），等能运行后看着补。
