# K04 三个模块改写与 Windows 等价核对

日期：2026-10-14。状态：完成。

## 做了什么

以 DM_RULESET=native 使用未修改的 dm/tools/patch_nso.py 改写 main、sdk、subsdk0，产物全部在 D:\kirby-work\patched。三个构建号未命中任何 D2R CUTS/OBS/PARAMS：无需复制或修改改写器。

为 Windows 验证复制了三个工具到 kirby/tools，文件开头均注明来源，dm/ 下零改动：

- verify_nsoimg.py：原样复制 dm/verify/nsoimg.py，仅加来源注释。
- structck_kirby.py：复制 structck.py；引用本地 verify_nsoimg；把 Unix grep 管道改为 Python 流式筛选 LLVM 输出，继续使用独立 LLVM 分母；hle.h 路径指回原仓库只读文件，明确 UTF-8 读取。检查判据未改。
- equiv_kirby.py：复制 equiv.py；引用本地 helper；Windows 进程启动从 fork 改为 spawn；负对照的候选集合排除 prfm/prfum 预取提示，但所有正向站点保持覆盖。

## 复现

环境：Python 3.14.7；lz4 4.4.5、capstone 5.0.9、unicorn 2.1.4；LLVM 22.1.7。

```powershell
python -m pip install lz4 capstone unicorn
$env:DM_RULESET="native"
$env:LLVM_BIN="C:/Users/hy367/scoop/apps/llvm/current/bin"
$env:DM_ROOT="D:/kirby-work"
foreach ($mod in 'main','sdk','subsdk0') {
  python -X utf8 -I dm/tools/patch_nso.py "D:\kirby-work\exefs\$mod" D:\kirby-work\patched $mod
  python -X utf8 -I kirby/tools/structck_kirby.py D:\kirby-work\patched $mod "D:\kirby-work\exefs\$mod"
  python -X utf8 -I kirby/tools/equiv_kirby.py D:\kirby-work\patched $mod "D:\kirby-work\exefs\$mod" --seed 1 --jobs 4 --tsv "D:\kirby-work\patched\$mod.equiv.tsv"
}
```

最终日志：D:\kirby-work\patched\<模块>.struct.log 和 <模块>.equiv.log。-X utf8 只使 Windows 输出可读；-I 保持隔离读取游戏数据。

## 测试中发现并解决的问题

首次 main 的正向验证已经零分歧，但两个 NOP 负对照漏抓：main+0x269c94 和 main+0x343468，均为 prfm。预取提示在本次 Unicorn 寄存器/内存可观察量中没有效果，改为 NOP 不能充当必然分歧的错误样本。依据 [Arm PRFM 指令说明](https://developer.arm.com/documentation/ddi0602/2026-03/Base-Instructions/PRFM--literal---Prefetch-memory--literal--?lang=en)，其效果由实现定义。

仅把预取提示从负对照候选中排除，不改游戏指令、不跳过正向等价、不降低零分歧或 300/300 负对照要求。修正后完整重跑三个模块全部通过。

## 没解决的问题与后续建议

Windows 只能执行 Unicorn 等价测试，不能运行改写后的 aarch64 游戏或 Apple 宿主。独占指令在对拍中按原工具规则两边同样降为普通读写，证明范围不包含真实并发内存序；门的运行时 ABI/宿主回写仍需 Mac 上 gatefn/H4 验证。K04 要求的结构与等价验收已完成。H1/H4 可使用 patched 目录及本报告的 svc 差集，不要将未触发的 SDK 包装直接当成必需实现清单。
