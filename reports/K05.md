## 实际加载与调用形态

取址不是直接向固定全局地址 str x0。卡比通过 GOT 读到全局槽指针，然后向该槽写入。原映像中的 GOT 值为 0，必须用 R_AARCH64_RELATIVE（1027）的 addend 还原，不能把 0 当成槽。

例如 nvnDeviceInitialize 名称在 0x8a6706；adrp/add 引用在 0x5183f4。GOT 0xa4dfb8 的重定位 addend 为全局槽 0xa60d98：

```asm
0x5183f4  adrp x1, #0x8a6000
0x5183f8  add x1, x1, #0x706
0x5183fc  mov x0, x20
0x518400  blr x19
0x518404  adrp x8, #0xa4d000
0x518408  ldr x8, [x8, #0xfb8]  // GOT -> 0xa60d98
0x51840c  str x0, [x8]           // 写函数指针到槽
```

实际调用通常为 adrp -> ldr GOT -> ldr 槽 -> br/blr。有的 GOT 指针被外提到 x19–x28，有的在分支汇合后共用一次间接调用；直接照抄 D2R 的单次 ldr 归属会漏计。工具按基本块控制流做有限集合固定点，合并分支候选；识别 adrp/adr/add/ldr/mov/csel，用 Capstone 精确清除其他指令写过的寄存器，调用时清除 ABI 易失寄存器。

交叉检查发现的两个共享调用点（两种目标都计一次）：

- main+0x517dec：`nvnTexturePoolInitialize` / `nvnSamplerPoolInitialize`。
- main+0x517e68：`nvnTexturePoolFinalize` / `nvnSamplerPoolFinalize`。

例如 0x517e54 的 b 跳过另一条 GOT 取址路径，汇合到 0x517e64/0x517e68。按源码线性向后找最后一次寄存器写入会漏掉 nvnTexturePoolFinalize；控制流合并覆盖两条路径。

## 验证、限制和后续建议

独立 Capstone 短指令模式抽查了 GOT -> 槽 -> br/blr，以及高优先级 nvnTextureGetTarget、nvnCommandBufferBindTexture、nvnColorStateSetAlphaTest。核查方法间的差异后补齐分支汇合。合成回归验证两个 GOT 取址分支在同一 blr 汇合时两个目标都计入，且下一次调用不会使用已被 ABI 清除的旧 x8。共享 6 项回归全部通过。

静态分析仅覆盖 main 中从已识别全局 NVN 槽直接或经 GOT 取得的间接调用，未推断任意堆对象/跨函数参数传递出来的回调；也没有把 sdk 驱动内部调用列入宿主 NVN 接口需求。D2R “已实现”只按登记分类，不能证明其实现满足卡比的全部语义。H1/H4 应以此完整新增清单安排接口实现，再用运行时记录确认热度；g_nops 中的四项需按卡比实际使用核实行为。
