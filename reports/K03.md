# K03 RomFS 文件格式摸底

日期：2026-10-14。状态：完成。

## 做了什么

生成 `docs/romfs_formats.md`：13 种扩展名的用途/魔数、每种 3 个 32 字节文件头样本（不足 3 个则全查）、CMP 内层分布及限制。新写 `tools/cmp_unpack.py`，识别 little-endian uint32 解压长度之后的 Zstandard 或 LZ4 frame，分块解压并核验长度。

`tools/romfs_formats.py` 全量检查压缩帧头，读取解压后 32 字节做格式分布；为 K06 另对 FRES/SARC/VFXB 容器作流式着色器定位，记录 FSHA/BNSH 的有效 8 字节签名、BOM 和声明长度边界。没有把全量解压资源写进磁盘或 git。名单保存在 `docs/cmp_shader_containers.tsv`，每个源文件一行，偏移相对于解压后的容器。

## 复现

```powershell
python -m pip install lz4 zstandard
python -X utf8 -I kirby/tools/romfs_formats.py D:\kirby-work\RomFS --docs kirby/docs --samples-out D:\kirby-work\unpacked_samples --scan-shaders
python -I kirby/tools/cmp_unpack.py '<输入.cmp 或 .cmpbin>' '<D:\kirby-work 下的输出文件>'
python -X utf8 -I kirby/tools/test_extractors.py
```

参考链接和实际样本路径见格式文档。实现没有复制社区代码；旧作 Star Allies 的 LZ4 包装资料仅供对照。

## 结果数字

| 包装 | 文件数 | Zstandard | LZ4 frame | 声明解压字节 |
|---|---:|---:|---:|---:|
| .cmp | 7201 | 5121 | 2080 | 11,433,388,448 |
| .cmpbin | 430 | 76 | 354 | 646,258,134 |

`.cmp` 内层：FRES 4287、XBIN 2080、SARC 486、VFXB 299、BFTTF 编码头 45、FFNT 4；合计 7201。`.cmpbin` 内层：FSAR 354、SARC 76；合计 430。全部压缩文件都识别为标准帧，不存在需要 raw deflate、zlib、LZ4 block、Yaz0 或其他 LZ77 变体解释的包装。

完整解压了覆盖每个包装/codec/内层组合的 8 个小样本，共 **624,924 字节**，前缀和实际长度一致。Zstandard 与 LZ4 的合成回归均通过；不符长度、截断输入和跨块着色器头也有回归覆盖。

扫描 **5148** 个可能含着色器的容器，共 **11,153,371,148** 解压字节；其中 **3554** 个文件含有效着色器头：**3397 FSHA、19412 BNSH**。FSHA 后为四空格，BNSH 后为四零字节，不能用同一种填充匹配。完整逐文件位置表约 400 KB。

## 没解决的问题与后续建议

BFTTF 内层编码、振动数据和部分 XBIN 的业务结构没有解析，用途猜测已明确标注；不影响 CMP 格式确定。这里统计的是容器头数量，不能当成去重着色器程序数量。

K06 应同时处理 24 个独立 BFSHA 和此名单中的 3554 个容器，进一步验证指针、变体和机器码布局。3554 个容器中有 326 个只有 BNSH 头，没有 FSHA，尤其不能只扫描 BFSHA。未对 XBIN 参数/字体/FSAR 音频进行嵌入着色器扫描。
